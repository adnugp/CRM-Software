# AI and document services

## Groq setup

The local Groq configuration was authenticated against the provider's model list and uses `openai/gpt-oss-120b`. Availability is account-specific; the older Llama template may need changing. Chat allows up to four tool rounds and a final response (five model calls maximum), so sequential project lookup, employee lookup, and task proposal can complete. Every call consumes provider quota; HTTP 429 means the current rate/quota limit was reached and does not trigger a paid upgrade. Live verification is `node scripts/verify-groq-assistant.mjs LOCAL_DEMO_EMAIL`; `--task-only` skips repeated finance queries to save quota. It proposes a task but never confirms or executes it.

Groq uses the existing hosted OpenAI-compatible adapter. Create your own key at https://console.groq.com/keys and select a currently available tool-capable model in your account. The example uses `llama-3.3-70b-versatile`; confirm its availability and account quotas before activation. No free quota or model availability is guaranteed by this project.

For local development, copy `functions/.env.groq.example` to `functions/.env.local`, and `functions/.secret.local.example` to `functions/.secret.local`. Edit the key privately in `.secret.local`, and update `AI_MODEL` if needed. Both active files are ignored by Git. Do not put credentials in frontend variables. Preserve any existing configuration when copying.

Stop the existing backend before starting `npm run dev:backend:groq`; do not start a second emulator on the same ports. The launcher checks the backend config and secret without printing the key. Firebase loads the local secret directly; the launcher does not copy it to the frontend environment. Make a current emulator snapshot before stopping (`node scripts/local-snapshots.mjs --once`). Restarting may require signing in again. Once enabled, chat sends authorized CRM context to Groq and consumes your provider quota. The assistant should show model mode instead of quick answers; verify a live answer and a task proposal before considering activation complete. This setup does not enable document scanning or embeddings.

For deployment, keep `AI_PROVIDER`, `AI_ENDPOINT`, and `AI_MODEL` in the Functions environment file for the real Firebase project (not `.env.local`, which is emulator-only). Store the key with `firebase functions:secrets:set AI_API_KEY --project YOUR_PROJECT_ID` using its interactive prompt, then deploy the functions to that explicit project. Never deploy the local demo project. Production deployment is a separate operation and has not been performed by local setup.

The retired `ai-chat-backend/server.js` exits without opening a port. Use Firebase authenticated callable functions. Each call requires an active workspace membership; conversations are private to one user and workspace. Model text and document text are untrusted. No write executes until `aiConfirm`; proposals expire after ten minutes and use domain mutation receipts to prevent duplicate writes. Updating a changed record requires a fresh proposal. No delete, payment posting, account administration or external messaging tool is available.

Configure deployment environment in the Firebase Functions environment file before deploying. Set `AI_PROVIDER=hosted` or `ollama`, `AI_MODEL` to an explicit tool-capable model, and `AI_ENDPOINT` to the full OpenAI-compatible chat completions endpoint, such as `https://your-provider/v1/chat/completions`. Hosted endpoints require HTTPS and the `AI_API_KEY` Firebase secret. Use `firebase functions:secrets:set AI_API_KEY`. Keys never belong in frontend environment variables. Hosted model requests transmit bounded chat history and authorized redacted record/tool results to the configured provider.

For local Ollama set `AI_PROVIDER=ollama`, `AI_MODEL` to an installed tool-capable model and `AI_ENDPOINT=http://127.0.0.1:11434/v1/chat/completions`. Run Ollama and Firebase emulators on the same machine; deployed Cloud Functions cannot reach your laptop's localhost. Remote Ollama must use HTTPS and an authenticated protected gateway. Ollama mode does not bind the hosted API key secret. Missing model/endpoint/provider configuration produces a visible unavailable error rather than simulated answers. Provider calls have a 20 second timeout, at most one transient retry, bounded tool rounds, ten calls per user per minute and the workspace plan's monthly `billing.limits.aiMessages` quota (default 1,000). Inactive billing blocks AI. Tests disable live calls.

`aiChat({workspaceId,conversationId?,message})` returns `{conversationId,response,citations,proposal?}`. Citation entries are verified records `{collection,id,label,page?,sheet?}`. Search is bounded and every returned count describes the returned page rather than a workspace-wide total. `aiConfirm({workspaceId,proposalId})` returns `{proposalId,result,duplicate}`. Record permission and active membership are rechecked after generation and before transactional mutations. Task tools use the application's existing embedded `project.tasks` array: they require an exact verified `projectId` and existing `taskId` for edits, preserve other tasks, and bind the parent project's expectedVersion. Creation needs name, verified employee assignee and dueDate; missing values require clarification. Employees must have a linked `userId` before AI can assign them work. Deadline listing uses the same embedded project tasks that appear in the UI.

Documents first upload into tenant-scoped private Storage paths and a `files` record with `quarantine=pending`. Managers/admins call `documentScan({workspaceId,fileId})`. Configure `DOCUMENT_SCAN_ENDPOINT` and the `DOCUMENT_SCAN_API_KEY` secret before deploying the scanner callable. The HTTPS service receives JSON `{mimeType,sha256,contentBase64}` and must return `{clean:boolean}` based on real malware scanning. The callable verifies the exact Storage generation and record version, then atomically sets the current version and file to `clean` or `rejected`, with an audit entry. A missing service, error or invalid verdict leaves the file pending. No client can release quarantine. Scanner configuration alone is not proof that a scanning service exists: operators must provision and test a real scanner. File downloads require the backend `fileDownload` authorization check and a clean selected version.

`aiIndexDocument({workspaceId,fileId})` accepts only accessible clean documents with verified SHA256/generation scan receipts and rechecks linked record permissions and version after extraction. Installed adapters are `pdf-parse` for PDF page text, `mammoth` for DOCX and `exceljs` for XLSX spreadsheets with sheet names and cached formula values (formulas never execute). Plain text/CSV/Markdown are supported directly. Documents are bounded to 15 MB and the first 40 text chunks (up to 40,000 characters) in an index. PDF extraction preserves page numbers; spreadsheet extraction preserves sheets. DOCX extraction supplies a record citation, as reliable page positions are unavailable. Descriptions and extracted text are data, never instructions.

For semantic retrieval configure `AI_EMBEDDING_ENDPOINT` to an OpenAI-compatible embeddings endpoint and `AI_EMBEDDING_MODEL` explicitly. Hosted embeddings use `AI_API_KEY`; to use a different key set `AI_EMBEDDING_AUTH=separate` and provision the `AI_EMBEDDING_API_KEY` secret. Ollama supports its `/v1/embeddings` endpoint for an installed embedding model. Embeddings must return `data:[{index,embedding:number[]}]`, with at most 2,048 finite dimensions. Model signatures and source record versions are stored with indexes. Query vectors rank authorized chunks by cosine similarity; old or mismatched indexes use lexical fallback until reindexed. With embeddings unconfigured, the response explicitly reports lexical-only capability. Search covers up to 100 accessible clean indexes from the first 500 metadata records, returns at most 12 chunks, and rechecks permissions/current source versions before text leaves the server. No embeddings/provider calls run during tests.

Scanned PDFs and images require optional OCR. Configure HTTPS `AI_OCR_ENDPOINT` plus `AI_OCR_API_KEY` Firebase secret before deploying. The OCR service receives `{mimeType,contentBase64}` and returns `{pages:[{page:1,text:"..."}]}`. Without OCR, image/scanned PDF indexing reports unavailable; it never claims to have read the document. OCR and embedding requests transmit authorized document text/content to explicitly configured services. Configure data retention with those providers to meet workspace requirements.

Chat and document indexing share the workspace monthly AI quota. Quota transactions recheck current membership, billing status and the plan limit. Conversations expire after `AI_RETENTION_DAYS` (default 30; bounded to 1–365 days). `cleanupAiRetention` runs hourly, deletes expired conversations/proposals in bounded batches, and rotates a persisted workspace cursor so later workspaces are covered. Document indexes follow source record versions and contain no conversation history. Operational audit/mutation receipt retention belongs to the workspace's audit policy.

Verification: `npm run build --prefix functions`, then `node --test functions/tests/ai.test.cjs`. The suite uses fake tool/store/embedding adapters and no paid provider. Live provider, scanner and OCR provisioning/credentials must be verified separately by the operator.

Management can use `summarizeFinance` for paginated invoice/payment totals, grouped by currency in integer minor units. It excludes cancelled records and reports invalid/missing amounts, filters and truncation explicitly. Employees/clients cannot use the tool. Tenant exports omit private conversations/proposals and ephemeral AI caches.

Local emulators offer deterministic CRM quick answers when AI_MODEL is absent. This is not a language model and never invokes a paid provider. It supports workspace/record summaries, project/task deadlines, management-only financial balances, indexed document excerpts, draft generic tender checklists, and an exact-name task command with confirmation. Production does not silently fall back. aiStatus reports the current mode and configuration availability without exposing secrets. Named record search checks up to ten pages and reports truncation. The UI shows sources, readable proposal fields, expiry, dismiss/retry/new-conversation controls.
